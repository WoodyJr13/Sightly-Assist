# Authorship and Assistance Log

## Purpose

Use this ledger to document the applicant's work, acquired code, mentorship, equipment support, critiques, and AI assistance. Add entries continuously rather than reconstructing them before submission.

## Entry template

| Date | Hours | Task or decision | Applicant contribution | Assistance received | External source or library | Verification performed | Evidence |
|---|---:|---|---|---|---|---|---|
| YYYY-MM-DD | 0.0 | Describe the work | What Ved personally designed, wrote, tested, analyzed, or changed | Person/tool and exact assistance | Citation, repository, paper, model, or package | Tests, derivation, manual review, experiment, or rewrite | Commit, notebook, sketch, recording, result file |

## Required distinctions

For every major component, identify:

- original design decisions;
- original code written by the applicant;
- code generated with AI assistance and subsequently reviewed or revised;
- code adapted from documentation or examples;
- third-party libraries used without modification;
- pretrained model architecture and weights;
- mentor suggestions;
- equipment or data supplied by others;
- independent verification performed by the applicant.

## Applicant-understanding checklist

Before a component is represented as part of the applicant's work, the applicant should be able to:

1. explain its purpose and assumptions;
2. derive or describe the relevant mathematics;
3. identify its inputs, outputs, and failure modes;
4. modify the implementation without relying on copied instructions;
5. design a test that could falsify its expected behavior;
6. interpret both successful and failed experimental results;
7. identify the external sources that influenced it.

## Current assistance record

The repository has been developed with substantial AI-assisted planning and code generation. This must be disclosed accurately. The applicant's final contribution should include independent review, local execution, targeted rewrites, experiment design, data collection, interpretation, and oral defense of the system.

Initial entries should be added when the applicant begins local review and testing. Do not fabricate retroactive hours or claim personal implementation that did not occur.

# Davidson Fellows Technology Submission Plan

## Category alignment

Sightly Assist is planned for the **Technology** category under **Artificial Intelligence**, with the specific field **edge AI for assistive computer vision and predictive collision-risk estimation**.

## Required project components

The final package will include:

1. A formal research report with a recognized bibliography style.
2. A visual model explaining the research, system, experiments, and findings.
3. A code package in accepted text/PDF/ZIP formats.
4. Documentation separating original code from acquired libraries and adapted methods.
5. A code index identifying the main pipeline, experiments, tests, and attributions.
6. A process essay.
7. A significance and benefit-to-society essay.
8. A maximum ten-minute unlisted video describing the work.
9. Two eligible nominators who know the work well.

## Formal research report outline

1. Title page
2. Abstract
3. Problem and social context
4. Prior work
5. Research gap
6. Research questions and hypotheses
7. System architecture
8. Mathematical model
9. Perception methodology
10. Depth and calibration methodology
11. Motion and camera-motion methodology
12. Collision-risk methodology
13. Uncertainty and abstention methodology
14. Free-space methodology
15. Hardware and software implementation
16. Dataset and scenario design
17. Baselines and ablations
18. Metrics and statistical methods
19. Results
20. Error analysis
21. Safety, ethics, and limitations
22. Reproducibility
23. Discussion and future work
24. Conclusion
25. Bibliography
26. Appendices

## Visual model plan

The visual model should be a PDF or slide deck containing:

- overall architecture diagram;
- sensor coordinate system;
- depth association illustration;
- temporal motion and camera-motion diagrams;
- closest-point-of-approach geometry;
- uncertainty and abstention flowchart;
- free-space corridor visualization;
- detector and tracker comparisons;
- annotated replay frames;
- latency and power breakdowns;
- baseline and ablation graphs;
- failure-case gallery;
- final wearable and mobile-interface photographs.

## Code submission plan

The final code package should contain:

- `CODE_INDEX.pdf`
- `ATTRIBUTIONS.pdf`
- `MAIN_PIPELINE.txt`
- `MATHEMATICAL_MODEL.txt`
- `INSTALLATION_AND_REPRODUCTION.pdf`
- `TEST_AND_EXPERIMENT_INDEX.pdf`
- repository snapshot ZIP
- licenses and notices for acquired software

## Process evidence to preserve now

- dated engineering log;
- Git commit history;
- experiment configurations and raw outputs;
- failed approaches and corrective decisions;
- hardware receipts and calibration records;
- time spent by phase;
- mentor and reviewer feedback;
- AI assistance disclosures;
- original sketches, equations, and design notes.

## Nominator strategy

- Technical nominator: a professor, engineering mentor, research mentor, or robotics adviser who can evaluate the technical depth and independence.
- Academic nominator: a teacher or professor who can describe persistence, intellectual growth, and the significance of the work.

Both should observe development and review evidence before the application period rather than seeing only the final product.

## Ten-minute video structure

- 0:00–0:40: problem and motivation
- 0:40–1:30: limitations of existing approaches
- 1:30–2:30: research question and original contribution
- 2:30–4:30: architecture and prototype
- 4:30–6:20: experiments and comparisons
- 6:20–7:30: results and failure analysis
- 7:30–8:20: social relevance
- 8:20–9:10: personal work and learning
- 9:10–10:00: limitations and future work

## Release gates

The project is not submission-ready until:

- the main claims are supported by repeatable experiments;
- all reported metrics can be regenerated from versioned data;
- all acquired code and models are attributed;
- every safety limitation is stated plainly;
- the applicant can explain and modify every core algorithm;
- the final report and visual model match the tested repository revision.
